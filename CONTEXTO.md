Guarda o original de cada nó, então a troca de idioma (`setLanguage`) retraduz ou volta ao inglês sem recarregar. Ignora `textarea`/`input`/`code`/`pre`/`contenteditable`/`[data-noi18n]`. Também traduz `alert`/`confirm`/`prompt`.

## Erros e correções conhecidas
- **⚠️ Disco D: (HD externo USB "USB3.0 high speed", 1,8 TB, Disco 1) com falhas de E/S — causa de lentidão/timeouts em tudo (2026-10-16)**: o log do Sistema tem 4.764 eventos `disk` ID 153 ("A operação de E/S … para o Disco 1 foi repetida") em 10 dias (desde 06/10, picos de 1.200+/dia), um a cada ~20–30 s. Cada um trava a leitura por ~20 s. Sintomas no app: ComfyUI não sobe em 3 min ("ComfyUI did not answer in time", pré-visualização do CAROLINE às 17:53) — `py-spy` mostrou o ComfyUI parado em `importlib.metadata.files()` → `stat` de arquivos do `comfyui_embedded_docs` (15.720 arquivos), com acessos isolados de 12–21 s; 1ª importação do chatterbox em ~4 min. Não é software: o mesmo arquivo responde em 0,04 s no 2º acesso. Diagnóstico: `Get-WinEvent -FilterHashtable @{LogName='System';ProviderName='disk';Id=153}`. Correção depende de hardware (cabo/porta/alimentação do HD, saúde do disco) ou de mover o projeto para o SSD `C:`.
- **Etapa de voz em erro "Voice worker did not answer in 1800 s" (projeto CAROLINE, 2026-10-16)**: outro resquício da mudança de pasta. O `venv_voice` não tem `torch` próprio; ele usa o do `.venv` por meio de `venv_voice\Lib\site-packages\_sleepy_main_torch.pth`, que ainda apontava para `H:\Meu Drive\PROJETOS\ominitubeclone\.venv\Lib\site-packages`. Como o Google Drive (`H:`) continua montado, o worker carregava torch/transformers (GBs) pelo Drive e não respondeu em 30 min. Correção: `.pth` (e scripts `activate*` dos dois venvs) apontando para `D:\0000000-PROJETOS\LeccorTube`. Teste: torch importa em 1,8 s do `D:`, Chatterbox Turbo gera áudio; a etapa de voz do CAROLINE rodou de novo e terminou (7/7 cenas em 2,6 min). Obs.: a 1ª importação do chatterbox depois disso leva ~4 min (numba compilando, disco frio); as seguintes, ~5 s.
- **`comfy_dir` no `config.json` apontava para `H:\Meu Drive\PROJETOS\ominitubeclone\ComfyUI_windows_portable`** (mesma causa): as etapas de imagem/vídeo rodariam o ComfyUI pelo Google Drive. Corrigido via `POST /api/config {comfy_dir: "D:\\0000000-PROJETOS\\LeccorTube\\ComfyUI_windows_portable"}`; `/api/setup` mostra `comfy.root` em `D:`.
- **Ao mover o projeto de pasta de novo**, trocar o caminho em: `.venv\pyvenv.cfg`, `venv_voice\pyvenv.cfg`, `venv_voice\Lib\site-packages\_sleepy_main_torch.pth`, `comfy_dir` do `config.json` (e opcionalmente os `Scripts\activate*`). Os `.exe` de `Scripts\` (pip.exe, uvicorn.exe, hf.exe…) têm o Python antigo embutido; o app não os usa (chama `python -m …`/`uv.exe`), mas à mão use `python -m pip` em vez de `pip.exe`.
- **"OMNITUBE could not start (code 103)" após mover o projeto de pasta**: o `logs/server.log` mostrava `No Python at 'H:\Meu Drive\PROJETOS\ominitubeclone\runtime\python\...\python.exe'`. Os `pyvenv.cfg` de `.venv` e `venv_voice` guardavam o caminho absoluto antigo (`H:\Meu Drive\PROJETOS\ominitubeclone`). Correção: trocar o caminho por `D:\0000000-PROJETOS\LeccorTube` nos dois `pyvenv.cfg`. **Ao mover o projeto de novo, repetir essa troca**, ou recriar os venvs pelo Setup Center → Repair.
- **Splash continuava "OMNITUBE / by Haris Ai" mesmo com `engine/window.py` já editado**: o launcher (`LECCORTUBE.exe`, cópia idêntica do `OMNITUBE.exe`) carrega o compilado legado `engine/window.pyc`, não o `.py`. Alterar só o `.py` não muda o app. Correção: substituir as strings no próprio `.pyc` e apagar o `engine/__pycache__/window.cpython-312.pyc` obsoleto.
- **Push bloqueado pelo GitHub Push Protection (GH013)**: o commit inicial levava o `config.json` com a `google_key` em texto puro (linha 81, "GCP API Key Bound to a Service Account"). Correção: `config.json` incluído no `.gitignore`, removido do índice (`git rm --cached`) e os commits locais que continham o arquivo (`3b0a18a`, depois `ced5acc`) foram desfeitos antes do push, então o segredo nunca chegou ao GitHub. As demais chaves do arquivo estão no formato `dpapi:` (criptografadas pelo Windows por usuário), mas também não devem ir para o repositório.

## Limitações conhecidas
- Os `*.pyc` e os `*.exe` estão no `.gitignore`, então os patches de marca existem só localmente. Num clone novo, o `engine/window.pyc` precisa ser modificado de novo e o `LECCORTUBE.exe` precisa ser regerado com `tools/rebrand_launcher.py`.
- Tradução: os prompts de estilo de imagem (aba Visual/Criar, ex.: "cinematic film still, natural soft lighting…") ficam em inglês de propósito — são exatamente o texto enviado ao gerador de imagens. Conteúdo do usuário (roteiros, prompts do projeto) nunca é traduzido.
- Tradução: textos novos que forem adicionados ao app.js/pyd só ficam traduzidos depois de rodar de novo o pipeline (`extract_*` → `build_sources.py` → traduzir os itens novos → `build_dict.py`). Itens novos = os de `source_en.json` que não estão em `translations.json`.
- Tradução: mensagens do servidor montadas com valores no meio (f-strings) são cobertas por fragmentos; algumas combinações raras podem sair metade traduzidas.
- O manifesto local de atualização usa a porta 7860, fixa na URL. Se o app rodar noutra porta (`OMNITUBE_PORT`), a busca falha com "Could not check for updates", mas também não baixa nada.
- O `tools/rebrand_app_pyd.py` também depende da versão 1.4.2 do `app.pyd` (`BLOB_OFF = 0xd77c50`), e não há como ter docstrings como folga: o saldo de bytes das trocas precisa ficar ≤ 0.
- Os offsets do `tools/rebrand_launcher.py` valem só para o `OMNITUBE.exe` 1.4.2.0 original. Outra versão do launcher exige mapear de novo o payload e o bloco `__main__`.
- O `config.json` precisa ser recriado manualmente em outra máquina, a partir do `config.example.json` ou pela interface do app.
